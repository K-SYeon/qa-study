# 테스트 종류

## 1. 기능 테스트 (Functional Testing)

소프트웨어의 기능이 요구 사항대로 정상 동작하는지 확인하는 테스트이다.

### 목적

사용자가 요구한 기능이 정상적으로 구현되었는지 검증한다.

### 대상

- 버튼 동작
- 입력 값 처리
- 로그인
- 결제
- 데이터 처리

### 테스트 과정

개발자가 작성한 코드가 작은 단위에서 정상 동작하는지 확인하고,
기능들이 연결된 후 전체 서비스 흐름까지 검증한다.

Unit Test
↓
Integration Test
↓
System Test
↓
Acceptance Test

---

## 1) Unit Test (단위 테스트)

가장 작은 단위의 기능이 의도한 대로 동작하는지 확인하는 테스트이다.

다른 기능과의 연결은 고려하지 않고 개별 단위 기능을 검증한다.

---

## 2) Integration Test (통합 테스트)

각 기능이 연결되었을 때 정상적으로 동작하는지 확인하는 테스트이다.

대상:

- 프론트엔드와 백엔드 연결
- API와 DB 연동
- 외부 시스템 연동

---

## 3) System Test (시스템 테스트)

완성된 시스템 전체를 하나의 서비스로 보고 검증하는 테스트이다.

실제 사용자가 서비스를 이용하는 흐름 기준으로 테스트한다.

예)

로그인
→ 기능 사용
→ 데이터 저장
→ 결과 확인

---

## 4) Acceptance Test (인수 테스트)

비즈니스 및 사용자 요구 사항을 만족하는지 최종 확인하는 테스트이다.

기술적인 동작보다 실제 서비스 목적에 맞게 사용할 수 있는지가 기준이 된다.

확인 사항:

- 요구 사항 충족 여부
- 운영 및 현업 사용 가능 여부
- 고객 승인 여부

---

# 2. 비기능 테스트 (Non-Functional Testing)

기능 동작 여부가 아닌 성능, 보안, 호환성 등 품질 요소를 검증하는 테스트이다.

---

## 1) 성능 테스트 (Performance Test)

시스템이 많은 사용자나 요청 상황에서도 정상적으로 동작하는지 확인한다.

### 종류

- 부하 테스트 (Load Test)
- 스트레스 테스트 (Stress Test)
- 안정성 테스트 (Stability Test)
- 확장성 테스트 (Scalability Test)

### 확인 지표

- 응답 속도
- 처리량
- CPU 및 메모리 사용량

예)

동시에 많은 사용자가 로그인할 때 정상적인 응답 속도를 유지하는지 확인

---

## 2) 보안 테스트 (Security Test)

시스템과 사용자의 정보를 안전하게 보호할 수 있는지 확인하는 테스트이다.

### 확인 사항

- 인증 및 권한 검증
- 개인정보 보호
- 데이터 암호화
- 세션 관리

예)

권한이 없는 사용자가 접근할 수 없는 페이지에 접근 가능한지 확인

---

## 3) 호환성 테스트 (Compatibility Test)

다양한 환경에서 정상적으로 동작하는지 확인하는 테스트이다.

### 확인 대상

- 운영체제
- 브라우저
- 디바이스

예)

같은 화면이 다른 브라우저에서도 정상적으로 표시되는지 확인

---

## 4) API 테스트 (Interface Test)

시스템 간 데이터 전달이 정상적으로 이루어지는지 확인하는 테스트이다.

### 확인 사항

- HTTP 응답 코드
- 데이터 구조
- 오류 메시지 처리

예)

결제 API 요청 후 정상적인 결과 데이터가 반환되는지 확인

---

# 3. 자동화 테스트 (Automation Testing)

반복적으로 수행해야 하는 테스트를 자동화하여 실행하는 방식이다.

## 목적

- 반복 테스트 효율 향상
- 테스트 시간 감소
- 오류 발견 가능성 증가

## 대상

- 기능 테스트
- API 테스트
- 회귀 테스트
- 호환성 테스트

## 특징

반복 실행이 필요한 테스트를 자동화하면
QA 효율을 높이고 사람이 수행하는 테스트의 부담을 줄일 수 있다.

---

# 4. Smoke Test

테스트를 본격적으로 진행하기 전에
해당 빌드가 테스트할 가치가 있는 상태인지 확인하는 테스트이다.

기본 기능이 동작하지 않는 상태에서 전체 테스트를 진행하면
불필요한 시간과 리소스가 발생하기 때문에 진행한다.

## 목적

- 테스트 가능한 빌드인지 판단
- 주요 기능의 정상 동작 여부 확인
- 개발 팀에 초기 오류 전달

## 특징

- 주요 기능 위주로 빠르게 확인
- 전체 테스트 전에 수행
- 하나라도 중요한 기능이 실패하면 추가 테스트 진행 여부를 판단

---

# 5. 회귀 테스트 (Regression Test)

기존 기능이 새로운 변경으로 인해 영향을 받지 않았는지 확인하는 테스트이다.

코드 수정이나 새로운 기능 추가 이후 기존 기능이 정상적으로 동작하는지 검증하기 위해 수행한다.

## 목적

- 기존 기능 손상 여부 확인
- 새로운 버그 발생 여부 확인
- 변경 사항으로 인한 영향 확인

## 수행 과정

1. 코드 변경 발생
2. 영향 범위 확인
3. 테스트 케이스 선정
4. 테스트 실행
5. 결과 확인 및 결함 수정
6. 재테스트 진행

---

## 회귀 테스트와 QA의 차이

| 구분 | 회귀 테스트 | QA |
| --- | --- | --- |
| 목적 | 변경된 부분으로 기존 기능 영향 확인 | 전체적인 품질 관리 |
| 범위 | 변경 사항 중심 | 시스템 전체 |
| 시점 | 기능 수정 및 추가 이후 | 개발 전체 과정 |

---

# 6. 정리

테스트는 기능이 정상 동작하는지 확인하는 기능 테스트와,
성능·보안·호환성 등 품질 요소를 확인하는 비기능 테스트로 나눌 수 있다.

또한 반복 테스트가 필요한 경우 자동화 테스트를 활용하고,
변경 사항으로 인해 기존 기능에 문제가 생겼는지 확인하기 위해 회귀 테스트를 수행한다.

QA는 단순히 오류를 찾는 것이 아니라,
다양한 테스트 방법을 통해 제품의 품질을 확인하고 개선하는 역할을 한다.
