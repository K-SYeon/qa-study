# Test Condition

## Test Condition이란?

Test Condition은 테스트를 통해 검증할 수 있는 시스템의 특정 요소, 동작 또는 요구 사항을 의미한다. 즉, 테스트에서 검증해야 할 단위를 말한다.

버튼 클릭과 같은 단순한 기능부터 계좌 유형에 따라 이자율이 정확하게 적용되는지와 같은 복잡한 기능까지 다양한 항목이 Test Condition이 될 수 있다.

또한 요구 사항과 테스트 실행을 연결하는 기준이 되며, 테스트를 체계적으로 수행할 수 있도록 구조와 명확성을 제공한다.

**예시**
- 계정 생성 기능에서 확인 이메일이 발송되는지 확인
- 비밀번호 검증이 정상적으로 수행되는지 확인
- 중복된 사용자 이름을 허용하지 않는지 확인

---

## 중요성

명확한 Test Condition이 없으면 테스트가 추측에 의존하게 되어 테스트 범위가 불명확해질 수 있다.

Test Condition을 정의하면 요구 사항과 테스트를 연결하여 테스트 범위를 확인할 수 있으며, 요구 사항이 제대로 검증되었는지 추적할 수 있다.

또한 테스트 대상과 목적을 문서화하기 때문에 팀원이 변경되더라도 일관성을 유지할 수 있으며, 은행·의료와 같은 규제 산업에서는 추적 가능한 Test Condition을 작성하는 것이 중요한 모범 사례로 활용된다.

---

## Test Scenario 및 Test Case와의 차이

| 구분 | 설명 |
|------|------|
| Test Scenario | 테스트의 전체적인 흐름을 정의한다. |
| Test Condition | 테스트해야 할 개별 요소를 정의한다. |
| Test Case | Test Condition을 기반으로 구체적인 입력, 수행 절차 및 예상 결과를 작성한다. |

**예시**

**Test Scenario**
- 사용자가 계정에 로그인하여 메시지를 확인한다.

**Test Condition**
- 로그인 버튼이 정상적으로 동작하는지 확인
- 잘못된 비밀번호를 입력했을 때 로그인에 실패하는지 확인
- 사용자가 자신의 메시지만 조회할 수 있는지 확인

**Test Case**
- Test Condition을 검증하기 위한 입력값, 수행 절차, 예상 결과를 작성한다.

---

## 유형

### 1. 기능 테스트 조건 (Functional Test Condition)

소프트웨어가 수행해야 하는 기능을 검증하는 조건이다.

**예시**
- 특정 입력 필드가 숫자만 입력받는지 확인

### 2. 비기능 테스트 조건 (Non-Functional Test Condition)

응답 속도, 성능, 사용자 인터페이스 반응성과 같이 소프트웨어가 동작하는 방식을 검증하는 조건이다.

**예시**
- 모바일에서 양식이 2초 이내에 로드되는지 확인

### 3. 경계 조건 (Boundary Condition)

허용 가능한 입력값의 경계를 검증하는 조건이다.

**예시**
- 나이 입력 범위가 18~65세인 경우
  - 17
  - 18
  - 65
  - 66

### 4. 오류 조건 (Error Condition)

유효하지 않거나 예상하지 못한 입력에 대해 시스템이 정상적으로 처리하는지 확인하는 조건이다.

**예시**
- 숫자를 입력해야 하는 항목에 "NaN"을 입력했을 때 오류 메시지가 표시되는지 확인

### 5. 환경 및 구성 조건 (Environment & Configuration Condition)

다양한 환경과 설정에서 정상적으로 동작하는지 확인하는 조건이다.

**예시**
- 오래된 브라우저에서 정상적으로 실행되는지 확인
- 다른 지역 설정에서도 정상적으로 동작하는지 확인

## 설계 및 구현

### 설계

Test Condition을 설계할 때 활용하는 대표적인 기법은 다음과 같다.

- 동등 분할
- 경계값 분석
- 의사결정표
- 상태 전환 테스트
- 사용 사례 분석

### 구현

테스트 관리 도구를 활용하여 Test Condition과 요구 사항을 연결하고 추적성을 관리한다.

이를 통해 모든 요구 사항이 테스트되었는지 확인할 수 있으며, 테스트 결과를 분석하여 테스트 전략을 개선할 수 있다.

---

## 모범 사례

- 원자적이고 구체적으로 작성한다.
- 비즈니스 목표에 맞게 작성한다.
- 우선순위를 설정한다.
- 추적성 매트릭스를 활용한다.
- 자동화를 적극 활용한다.

---

## 주의 사항

- 너무 광범위하거나 모호하게 작성하지 않는다.
- 부정적인 상황도 함께 고려한다.
- 문서화를 생략하지 않는다.
- 변경 사항에 맞게 지속적으로 업데이트한다.
- 이해관계자의 의견을 반영한다.

---

## 정리

Test Condition은 테스트를 통해 검증해야 할 항목을 정의하는 단계이다.

요구 사항을 기반으로 테스트 범위를 구체화하며, 이후 Test Scenario와 Test Case를 작성하기 위한 기준으로 활용된다.
