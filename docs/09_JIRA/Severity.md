# Severity

## 개요

Severity(심각도)는 테스트에서 발견된 결함이 시스템이나 기능에 얼마나 심각한 영향을 미치는지를 나타내는 기준이다.

## 학습 목표

- Severity의 개념을 이해한다.
- Priority와 Severity의 차이를 이해한다.
- Severity의 대표적인 단계를 이해한다.
- QA에서 결함의 심각도를 판단하는 방법을 이해한다.

## 학습 내용

### 1. Severity란?

Severity(심각도)는 테스트에서 발견된 결함이 **시스템이나 기능에 얼마나 심각한 영향을 미치는지** 나타내는 기준이다.

예를 들어 로그인 자체가 되지 않는 경우:

```text
사용자가 로그인을 할 수 없음
→ 핵심 기능 사용 불가
→ Severity 높음
```

반대로 버튼의 글자가 조금 잘리는 경우:

```text
버튼은 정상적으로 클릭 가능
→ 기능에는 큰 영향 없음
→ Severity 낮음
```

### 2. Priority와 비교

Priority와 Severity는 서로 다른 기준이다.

| 구분 | 의미 |
|---|---|
| **Priority** | 얼마나 빨리 처리해야 하는가 |
| **Severity** | 문제가 얼마나 심각한가 |

예를 들어 화면의 문구가 살짝 잘린 문제는 기능에 거의 영향이 없기 때문에 Severity가 낮을 수 있다.

하지만 해당 화면이 중요한 이벤트 페이지이고 곧 오픈될 예정이라면 빠른 수정이 필요할 수 있으므로 Priority는 높게 설정할 수 있다.

따라서 **Severity가 낮더라도 상황에 따라 Priority가 높을 수 있다.**

### 3. QA에서 Severity가 필요한 이유

QA가 Bug를 발견했을 때 단순히 버그가 있다고 전달하는 것보다 **해당 Bug가 기능에 어느 정도의 영향을 주는지 판단할 수 있어야 한다.**

예를 들어:

```text
Bug A
로그인 자체가 불가능함
→ Severity 높음
```

```text
Bug B
버튼 문구가 약간 잘림
→ Severity 낮음
```

이렇게 결함의 심각도를 구분하면 어떤 결함이 시스템이나 기능에 더 큰 영향을 주는지 파악하기 쉽다.

### 4. Severity의 대표적인 단계

Severity는 결함이 기능과 시스템에 미치는 영향의 크기를 기준으로 판단하며, **회사나 프로젝트에 따라 단계와 기준이 다를 수 있다.**

| Severity | 의미 | 예시 |
|---|---|---|
| **Critical** | 시스템이나 핵심 기능을 사용할 수 없을 정도로 매우 심각한 결함 | 결제 시스템 전체가 작동하지 않음 |
| **Major** | 주요 기능이 정상적으로 동작하지 않는 심각한 결함 | 로그인할 수 없음 |
| **Minor** | 기능은 사용할 수 있지만 일부 기능이나 화면에 문제가 있는 결함 | 특정 조건에서 검색 결과가 잘못 표시됨 |
| **Trivial** | 기능에는 거의 영향이 없고 UI나 문구 등 사소한 문제 | 버튼 문구의 오타 |

#### 4-1. Critical

가장 심각한 수준으로, 시스템 전체나 핵심 기능에 심각한 문제가 발생해서 서비스를 정상적으로 사용하는 것이 어려운 경우이다.

예:

- 결제 시스템 전체가 작동하지 않음
- 서비스 접속 자체가 불가능함

#### 4-2. Major

주요 기능에 문제가 발생한 경우이다.

시스템 전체가 다운된 것은 아니지만 중요한 기능을 정상적으로 사용할 수 없는 상황이다.

예:

- 로그인할 수 없음
- 회원가입이 완료되지 않음
- 상품을 구매할 수 없음

#### 4-3. Minor

기능 자체는 사용할 수 있지만 일부 기능이나 특정 상황에서 문제가 발생하는 경우이다.

예:

- 특정 조건에서 검색 결과가 잘못 표시됨
- 특정 화면에서 일부 정보가 잘못 표시됨

#### 4-4. Trivial

기능에는 거의 영향을 주지 않는 아주 사소한 문제이다.

대표적으로 UI나 문구 관련 문제가 있다.

예:

- 버튼 문구의 오타
- 문구의 띄어쓰기 오류

### 5. Severity 단계 비교

로그인 기능을 예로 들면 다음과 같이 구분할 수 있다.

```text
Critical
→ 서비스 자체에 접속할 수 없음

Major
→ 로그인 기능을 사용할 수 없음

Minor
→ 로그인은 되지만 특정 상황에서 사용자 정보가 잘못 표시됨

Trivial
→ 로그인 화면의 안내 문구에 오타가 있음
```

### 6. Priority와 Severity를 함께 판단하기

Priority와 Severity는 반드시 같은 수준으로 판단되는 것은 아니다.

#### 예시 1. 결제 기능 장애

```text
상황:
쇼핑몰에서 결제 버튼을 눌러도 결제가 진행되지 않음

- 로그인 정상
- 상품 검색 정상
- 장바구니 정상
- 결제만 불가능
- 모든 사용자가 동일한 문제를 겪음

Severity: Critical
Priority: High
```

결제는 서비스의 중요한 기능이고 모든 사용자가 결제를 할 수 없으므로 결함의 심각도와 처리 우선순위가 모두 높다고 판단할 수 있다.

#### 예시 2. 프로모션 버튼 문구가 잘림

```text
상황:
쇼핑몰의 이벤트 페이지에서 버튼 문구가 잘려 표시됨

- 버튼 자체는 정상적으로 작동
- 이벤트 참여도 정상적으로 가능
- 오늘 오후 6시에 대규모 프로모션 시작

Severity: Trivial
Priority: High
```

서비스를 이용하는 데에는 문제가 없으므로 Severity는 낮게 판단할 수 있다.

하지만 중요한 프로모션이 곧 시작될 예정이므로 빠르게 수정해야 할 필요성이 있어 Priority는 높게 판단할 수 있다.

#### 예시 3. 관리자 통계의 매출 금액 오류

```text
상황:
관리자만 사용하는 통계 페이지에서 매출 금액이 잘못 계산됨

- 일반 사용자는 해당 페이지를 볼 수 없음
- 관리자만 사용
- 현재 관리자도 해당 페이지를 당장 사용할 계획이 없음
- 실제 매출 데이터를 잘못 보여줌

Severity: Major
Priority: Low
```

실제 데이터를 잘못 계산하는 기능 오류이므로 Severity는 높게 판단할 수 있다.

하지만 일반 사용자에게 영향을 주지 않고 당장 해당 페이지를 사용할 계획도 없으므로 Priority는 낮게 판단할 수 있다.

## 핵심 정리

- Severity는 결함이 시스템이나 기능에 미치는 **심각도**를 나타낸다.
- Priority는 Issue를 **얼마나 빨리 처리해야 하는지**를 나타낸다.
- Severity와 Priority는 서로 다른 기준이다.
- Severity가 높다고 해서 Priority가 반드시 높은 것은 아니다.
- Severity가 낮더라도 상황에 따라 Priority가 높을 수 있다.
- 대표적인 Severity 단계에는 Critical, Major, Minor, Trivial이 있다.
- 회사나 프로젝트에 따라 Severity의 단계와 기준은 달라질 수 있다.
