# Issue Type

## 개요

JIRA에서 Issue의 종류를 구분하기 위한 것이다.

Issue의 성격에 따라 적절한 Issue Type을 선택하여 업무를 관리할 수 있다.

## 학습 목표

- Issue Type의 개념을 이해한다.
- Task, Story, Bug의 차이를 이해한다.
- QA 업무에서 각 Issue Type이 어떻게 활용되는지 이해한다.
- 업무의 성격에 맞는 Issue Type을 구분할 수 있다.

## 학습 내용

### 1. Issue Type이란?

JIRA에서 **Issue Type은 Issue의 종류를 구분하기 위한 것**이다.

프로젝트에서 관리하는 업무의 성격이 서로 다르기 때문에 Issue Type을 사용하여 구분한다.

대표적인 Issue Type은 다음과 같다.

- Task
- Story
- Bug

### 2. Task

**Task(작업)**는 프로젝트에서 수행해야 하는 일반적인 작업을 말한다.

QA에서는 다음과 같은 업무를 Task로 관리할 수 있다.

- 로그인 기능 테스트
- 회원가입 테스트 케이스 작성
- 검색 기능 테스트
- 테스트 결과 정리

실습에서 생성한 `로그인 기능 테스트` Issue도 Task로 생성했다.

```text
Issue Type: Task
Summary: 로그인 기능 테스트
```

### 3. Story

**Story(스토리)**는 일반적으로 사용자의 관점에서 어떤 기능이나 가치를 제공하기 위한 요구사항을 관리할 때 사용한다.

보통 개발 과정에서 **사용자에게 어떤 기능을 제공하는가**를 중심으로 작성한다.

QA에서는 Story를 기준으로 테스트 케이스를 작성하거나 기능을 검증할 수 있다.

예를 들어 다음과 같은 요구사항을 Story로 관리할 수 있다.

```text
사용자는 이메일과 비밀번호를 입력하여 로그인할 수 있어야 한다.
```

### 4. Bug

**Bug(버그)**는 소프트웨어에서 기대한 결과와 실제 결과가 다르게 나타나는 결함을 관리하기 위한 Issue Type이다.

테스트 과정에서 결함을 발견했다면 Bug Issue로 등록하여 수정 과정을 관리할 수 있다.

QA에서 가장 직접적으로 많이 사용하는 Issue Type 중 하나이다.

예를 들어 로그인 기능을 테스트했을 때 다음과 같은 문제가 발생할 수 있다.

```text
기대 결과:
로그인 버튼을 클릭하면 로그인되어야 한다.

실제 결과:
로그인 버튼을 클릭해도 아무런 동작이 발생하지 않는다.
```

이러한 경우 해당 결함을 Bug Issue로 등록할 수 있다.

### 5. Issue Type 비교

| Issue Type | 의미 | QA 예시 |
|---|---|---|
| **Task** | 수행해야 하는 일반적인 작업 | 로그인 기능 테스트 |
| **Story** | 사용자 관점의 기능/요구사항 | 사용자가 로그인할 수 있어야 함 |
| **Bug** | 발견된 결함 | 로그인 버튼 클릭 시 동작하지 않음 |

### 6. QA에서 Issue Type이 중요한 이유

QA가 JIRA에서 Issue를 관리할 때 **Issue가 어떤 성격인지 명확하게 구분할 수 있기 때문**이다.

업무의 성격에 따라 Issue Type을 구분하면 Project 안에 많은 Issue가 있더라도 각각의 목적을 쉽게 파악할 수 있다.

예를 들어:

```text
QA Testing

Task
└── 로그인 기능 테스트

Story
└── 사용자가 로그인할 수 있어야 함

Bug
└── 로그인 버튼 클릭 시 동작하지 않음
```

이처럼 Issue Type을 구분하면 작업, 요구사항, 결함을 명확하게 관리할 수 있다.

## 핵심 정리

- Issue Type은 JIRA에서 Issue의 종류를 구분하기 위한 것이다.
- **Task**는 수행해야 하는 일반적인 작업을 의미한다.
- **Story**는 사용자 관점의 기능이나 요구사항을 관리할 때 사용한다.
- **Bug**는 소프트웨어에서 발견된 결함을 관리할 때 사용한다.
- Issue Type을 구분하면 Project 내의 업무와 결함을 목적에 따라 명확하게 관리할 수 있다.
