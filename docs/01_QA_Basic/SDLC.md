# SDLC (Software Development Life Cycle)

## 1. SDLC란?

SDLC(Software Development Life Cycle)는 소프트웨어 개발 생명주기를 의미한다.

새로운 소프트웨어를 개발할 때
계획 → 요구 사항 분석 → 설계 → 구현 → 테스트 → 배포
과정을 거쳐 개발하는 방식을 말한다.

---

# 2. SDLC 단계별 QA 역할

## 1) 계획 단계

제품의 목적과 사용자를 예상하고 전체적인 개발 방향을 계획하는 단계이다.

### QA 역할

- 사용자가 원하는 기능인지 확인
- 불필요한 기능은 없는지 검토
- 사용자가 제품을 사용하는 상황을 고려하여 테스트 관점의 시나리오 구상

---

## 2) 요구 사항 분석 단계

기획된 내용을 바탕으로 제공할 기능과 부족한 부분, 위험 요소를 확인하는 단계이다.

### QA 역할

- 제품의 위험 요소 확인
- 개선이 필요한 부분 의견 공유
- 개발 후 수정 비용이 증가할 수 있는 부분을 사전에 확인

---

## 3) 설계 단계

기능 구현 방법과 함께 테스트 방법을 고려하는 단계이다.

### QA 역할

- 기능 검증 방법 설계
- 필요한 테스트 환경, 인력, 일정 확인
- 테스트 종료 기준(Sign-Off) 수립

예)

- 선정된 Test Case 100% 수행
- 중결함 이상 0건
- 사전에 협의된 성능 기준 통과

---

## 4) 구현 단계

실제 개발이 진행되는 단계이다.

### QA 역할

- Test Case 작성
- 자동화 테스트 스크립트 작성
- 설계 내용대로 개발이 진행되는지 확인
- 변경 사항 발생 시 협업을 통한 확인

---

## 5) 테스트 단계

개발된 기능이 요구 사항대로 동작하는지 확인하는 단계이다.

### QA 역할

- 작성한 Test Case 수행
- 결함 확인 및 보고
- 필요 시 성능 테스트, 보안 테스트 등 비기능 테스트 진행
- 품질 지표 제공

---

## 6) 배포 단계

완성된 제품을 사용자에게 제공하는 단계이다.

### QA 역할

- 라이브 환경에서 이상 여부 확인
- 사용자 의견 확인
- 수정이 필요한 부분에 대한 후속 일정 확인

---

# 3. SDLC 모델

## 1) Waterfall Model (폭포수 모델)

각 단계를 순차적으로 진행하는 개발 방식이다.

### 특징

- 단계가 명확하게 구분됨
- 문서화가 체계적임
- 요구 사항이 명확한 프로젝트에 적합

하지만 이전 단계로 돌아가기 어렵기 때문에 개발 후 수정 발생 시 비용이 증가할 수 있다.

### QA 역할

- 각 단계별 검토 진행
- 테스트 단계뿐 아니라 개발 초기부터 참여하는 Shift-left 방식 활용

---

## 2) Agile Model (애자일 모델)

작은 단위로 기능을 나누어 빠르게 개발하고 사용자 피드백을 반영하는 방식이다.

### 특징

- 짧은 주기로 개발 진행
- 지속적인 소통을 통해 요구 사항 변경에 유연하게 대응 가능

### QA 역할

- 스프린트 범위 내 테스트 계획 및 수행
- 변경 사항 지속 확인
- 변경된 기능에 대한 Test Case 유지보수

---

# 4. 정리

SDLC는 제품을 어떻게 만들 것인가에 초점을 둔 개발 생명주기이다.

QA는 테스트 단계에서만 활동하는 것이 아니라,
요구 사항 분석부터 배포 이후까지 전체 과정에서 품질을 관리하는 역할을 한다.
